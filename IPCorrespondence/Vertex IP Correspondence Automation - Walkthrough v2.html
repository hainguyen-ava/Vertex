00 00-OVERVIEW

Business Overview & Problem Statement

Today, Vertex IP Operations manually reviews every incoming email, identifies the patent family reference, locates (or creates) the matching folder, moves the email, and tracks exceptions. This consumes significant operational effort and relies heavily on individual knowledge of folder structures and reference formats.

Today — manual effort

  • Review incoming emails one by one
  • Identify patent family references by eye
  • Search for the matching family folder
  • Create folders when none exists
  • Move emails to the right location
  • Track and explain filing exceptions

Phase 1 — automated solution

  • Agent reads every new email automatically
  • Reference identified from subject, body, or quoted thread
  • Reference validated against folder-naming rules
  • Folder found or created, email filed automatically
  • Every action logged for audit
  • One daily report to business owners — new folders & exceptions
01 01-PROCESS

High-Level Business Process Flow

The agent reads every new email, scans for a reference number, validates the folder-naming rule, and either files the email or raises a documented exception — then sends one consolidated report to business owners at the end of the day.

02 02-TECHNICAL

Technical Implementation Flow

Phase 1 is implemented on four coordinated components: Outlook + Power Automate for ingestion and filing, Azure OpenAI (via Azure AI Foundry) for reference extraction, a deterministic Power Automate validator for folder-naming rules, and Dataverse for the activity/exception log that feeds a second, independent daily-report flow.

Technical implementation workflow — full detail in the Vertex IP Technical Design Document (TDD). Interactive: use the Live/Still toggle inside the diagram to play the trace animation. Open full-screen ↗

By design: Azure OpenAI never branches or decides. It always returns structured JSON only — Power Automate owns the found/not-found and valid/invalid decisions, deterministically.

Agent: Instructions + Skill (Azure OpenAI via Foundry)

  • Instructions — system prompt encodes Ref # lead-in phrases and known matter prefixes
  • Skill — trainable, extensible component that identifies and maps the Ref #; business can add new mapping rules without rewriting instructions
  • Output — always structured JSON only (reference, is_vertex, segments, normalized_value, confidence) — no agent-side decisioning

Folder Rule Validator (deterministic, Power Automate)

  • Condition/Switch action — not a model call
  • Vertex reference: exactly 2 segments (e.g. 00-113)
  • Non-Vertex reference: prefix + 2 segments (e.g. SEM-24-783)
  • Invalid format → exception, no auto-filing
03 03-SIGNOFF

Functional Requirements (FR-1 – FR-9)

Nine consolidated requirement areas, each traceable to the detailed functional design and the solution architecture — the basis for client review and sign-off.

IDRequirement AreaSummary
FR-1Email IngestionMonitor the shared mailbox; read every new email, reply, and acknowledgement within minutes of receipt.
FR-2Reference (Ref #) IdentificationScan subject first, then body, then quoted history; recognize common lead-in phrases and known matter prefixes.
FR-3Reference NormalizationStandardize detected references — uppercase, separators, country codes, subcase suffixes, spacing.
FR-4Folder Rule ValidationVertex references require exactly 2 segments; non-Vertex references require prefix + 2 segments. Failures raise an Invalid Format exception.
FR-5Folder ManagementSearch for a matching folder; move the email if found, create a new folder if not — every creation is audited.
FR-6Automated Filing RulesSingle valid family → auto-file; folder located → move; folder missing → create, move, and record.
FR-7Exception HandlingNo reference, multiple references, subject/body conflicts, invalid format, or attachment-only references all route to manual review with a documented reason.
FR-8Audit LoggingEvery processed email generates an audit entry — message ID, sender, subject, reference, folder, result, timestamp, exception type.
FR-9Daily ReportingOne daily report to business owners — executive summary, new folders, filing activity, exceptions, and normalization activity.

Full requirement-level detail (FR-1.1 through FR-9.6) is in the Vertex IP FDD, Section 5 — Functional Requirements, and in Vertex IP FDD - Functional Requirements.md.

04 04-EXCEPTIONS

Exception Handling Rules

Every scenario the agent cannot resolve automatically is documented, left untouched for manual review, and included in the daily report — the agent never guesses.

ExceptionConditionAction
No Reference FoundNo valid reference detected anywhere in the emailLeave in Inbox, add to exception queue, include in daily report
Multiple Family ReferencesMore than one valid reference detectedNo auto-filing; route for manual review
Subject/Body ConflictDifferent references in subject vs. bodyDo not prioritize automatically; route for manual review
Conflicting Quoted HistoryLatest vs. older quoted references disagreeCreate exception; require manual review
Invalid FormatReference fails Folder Rule ValidationLeave untouched, log Invalid Format exception, route for review, include in report
Attachment OnlyReference appears only inside an attachmentNot processed in Phase 1; create exception (OCR is out of scope)
05 05-ROADMAP

Future Phase Roadmap

Phase 1 already uses Azure OpenAI (via Foundry) for reference extraction. The items below are additional, not-yet-scoped enhancements for future phases.

Future Attachment Processing

OCR and PDF parsing so references found only inside attachments can be identified and filed automatically.

Future Copilot Studio Agent

A conversational agent so business users can ask things like “Show all correspondence for SEM-26-788” or “What folders were created today?”

Future Power BI Dashboard

Operational KPIs — processing volume, automation success rate, open exceptions, top active patent families, trend analysis.
